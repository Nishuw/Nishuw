## Projetos selecionados

### DocRAG BR
Projeto desenvolvido individualmente durante a RAISE Summit Hackathon, em Paris, para processamento de documentos financeiros brasileiros.

O sistema combina RAG, processamento estruturado de PDFs e Vision LLM para responder perguntas sobre documentos contendo texto, tabelas e gráficos. Inclui chunking, embeddings, retrieval, grounding por página e uma camada de auditoria numérica que verifica valores utilizados nas respostas contra o documento de origem.

→ [github.com/Nishuw/DocRAG-BR](https://github.com/Nishuw/DocRAG-BR)

`Tech: Python · RAG · PyMuPDF · pdfplumber · ChromaDB · Vision LLM · OpenRouter`

### Tyrel
Assistente pessoal de IA para desktop construído com foco em memória persistente, ferramentas e execução local. Possui arquitetura baseada em skills, onboarding, histórico de interação, TTS e capacidade de executar ações no desktop e sistema operacional.

A arquitetura separa memória de curto prazo e memória persistente, permitindo que o agente utilize informações acumuladas ao longo das interações.

`Tech: Tauri 2 · Rust · Python · LLMs · memória persistente · TTS · skills · desktop automation`

### Clarinha — AI Knowledge Assistant
Pipeline de IA para ingestão, processamento e recuperação de conhecimento a partir de documentos, utilizando RAG e integração com agentes.

O projeto trabalha com extração e estruturação de conteúdo, chunking, recuperação semântica e exposição do conhecimento através de APIs e ferramentas compatíveis com agentes.

`Tech: Python · RAG · LLMs · MCP · APIs · Swagger`

### TRON / agent_tron
Agente autônomo orientado à execução de tarefas via CLI, capaz de interagir com filesystem e terminal utilizando ferramentas externas. O projeto explora uma arquitetura de agente voltada menos para conversação e mais para planejamento → execução → observação → correção.

`Tech: CLI · Claude · filesystem · terminal · tool use · agent architecture`

### Circuito de Integração — Mix Fiscal
Plataforma interna de testes e homologação de integrações com APIs fiscais, desenvolvida para facilitar a validação de fluxos entre sistemas.

A aplicação apresenta respostas da API em duas camadas: uma explicação técnica para desenvolvedores e outra orientada ao negócio, traduzindo conceitos como ICMS, PIS/COFINS, NCM/CEST, CST, CFOP e MVA.

`Tech: React · Zustand · APIs REST · Swagger/OpenAPI · jsPDF`

## Como trabalho

- Começo pelo problema e pelos requisitos de negócio antes de escolher a tecnologia
- Prefiro sistemas observáveis e instrumentados a protótipos que funcionam apenas em demonstrações
- Uso LLMs como componentes de sistemas, não como substitutos da arquitetura
- Valorizo APIs bem definidas, separação de responsabilidades e documentação
- Em sistemas de IA, priorizo grounding, controle de contexto, ferramentas e mecanismos de validação
- Utilizo projetos pessoais e hackathons para experimentar novas arquiteturas rapidamente
